# 함께 운동 시간표 UI 설계

## 1차 계획: 체육센터 입구의 강습 안내판

두 사람이 로비에서 휴대폰 한 대를 함께 보며 자신의 수업을 고른다. 첫 화면의 주인공은 홍보 문구나 통계가 아니라 **월요일부터 일요일까지 펼쳐진 두 사람의 요일 선택판**이다. 결과에서는 A와 B의 수업 시간을 같은 열에 두어 겹침과 간격을 읽게 한다. 실제 강좌명, 강좌번호, 월 회비는 안내판의 내용이지 장식이 아니다.

### 색 토큰

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--blue` | `#1746C7` | 시간표 머리판, 선택 상태, 주요 동작 |
| `--ink` | `#182640` | 본문과 시간, 이름 |
| `--muted` | `#53627A` | 설명과 보조 정보, 흰 바탕에서도 읽을 수 있는 농도 |
| `--ground` | `#EDF1F7` | 밝고 차가운 시설 안내판 주변 바탕 |
| `--paper` | `#FFFFFF` | 입력판과 강좌 행 |
| `--line` | `#C4CEDD` | 사람·시간·메타데이터의 구획 |

색을 추가하지 않고 흰색과 파란색의 면적, 선 굵기로 위계를 만든다. 초록·크림·그라데이션·카드 그림자는 사용하지 않는다. A/B는 글자로 구분하며 선택 요일에는 체크 표시도 붙인다.

### 서체

- 한국어 안내판의 간결한 고딕을 위해 `Apple SD Gothic Neo`, `Malgun Gothic`, `sans-serif` 순서의 로컬 서체를 쓴다. 별도 다운로드와 외부 글꼴 요청이 없다.
- 제목 32–48px, 절 제목 24px, 강좌 시간 22–26px, 본문·입력 16px, 보조 정보 13–14px의 배율을 쓴다. 제목은 통째로 한 색이며 한 단어만 강조하지 않는다.
- 시간과 금액에는 같은 서체의 `tabular-nums`를 적용한다. 메타데이터에 모노스페이스를 쓰지 않는다. 한국어는 어절 단위로 줄바꿈하고 긴 해시·URL만 어디서든 줄바꿈한다.
- 본문은 왼쪽 정렬, 요일과 A/B 표지만 가운데 정렬, 비교하는 금액은 오른쪽 정렬한다. 설명은 약 65자 폭 이내로 제한한다.

### 배치 대안과 선택

대안 A는 제목 옆에 예시 시간표 그림을 두는 방식이다. 예시와 실제 입력을 혼동할 수 있고 좁은 화면에서 핵심 폼이 밀린다. **대안 B인 실제 입력판을 히어로에 연결하는 방식**을 선택한다. 요일 선택과 이후 조건이 하나의 안내판을 이룬다. 제목이 있는 파란 머리판 하나가 기억에 남는 요소다.

입력 / 넓은 화면:

```text
함께 운동 시간표                        조건 입력   데이터 근거
┌──────────────────────────────────────────────────────────┐
│ 같은 날, 각자의 운동.                  일산스포츠센터      │
│ 두 사람의 요일·시간·월 회비를 맞춰보세요.  데이터 기준 월     │
├────────────────────────────┬─────────────────────────────┤
│ A의 운동 조건              │ B의 운동 조건               │
│ 월 화 수 목 금 토 일       │ 월 화 수 목 금 토 일        │
│ 시작 시각       종료 시각  │ 시작 시각       종료 시각   │
│ 선호 종목                  │ 선호 종목                   │
│ 제외 종목                  │ 제외 종목                   │
│ 최대 월 회비               │ 최대 월 회비                │
├────────────────────────────┴─────────────────────────────┤
│ 조건 적용 설명                     [함께 갈 조합 찾기]    │
└──────────────────────────────────────────────────────────┘
데이터 출처와 해석상의 주의
```

입력 / 360px:

```text
함께 운동 시간표
조건 입력           데이터 근거
┌──────────────────────────┐
│ 같은 날, 각자의 운동.    │
│ 설명 / 센터 / 기준 월    │
├──────────────────────────┤
│ A의 운동 조건            │
│ 월 화 수 목 금 토 일     │
│ 시작        종료         │
│ 선호 / 제외 / 월 회비    │
├──────────────────────────┤
│ B의 운동 조건            │
│ 같은 순서의 입력         │
├──────────────────────────┤
│ [함께 갈 조합 찾기]      │
└──────────────────────────┘
```

결과:

```text
두 사람의 운동 시간표                  [조건 수정]
조건 요약
 A   요일 / 시간 / 예산 / 종목
 B   요일 / 시간 / 예산 / 종목
공유 URL

동시 조합   n개             연속 조합   n개 (해당 절 링크)
┌──────────────────────────────────────────────────────────┐
│ 공통 요일 화, 목                       합계 월 135,000원  │
│ A   18:00–18:50    TRX / 강습반 원문         월 100,000원 │
│ B   18:00–18:50    농구 / 강습반 원문        월  35,000원 │
│ 겹치는 시간 50분                         원문 근거 보기  │
└──────────────────────────────────────────────────────────┘
모바일: A/B 행은 유지하고 각 행 안에서 강좌명·회비를 시간 아래로 배치

둘 다 없을 때: 최소 변경 제안
┌──────────────────────────────────────────────────────────┐
│ 무엇을 바꾸는지 (엔진의 검증된 문장)                      │
│ 추가 예산 / 추가 요일 / 확장 분                           │
│ [변경한 조건으로 다시 보기]                               │
│ 그 조건을 입증하는 실제 A/B 강좌 행                       │
└──────────────────────────────────────────────────────────┘
```

근거: 제목 아래 파일 메타데이터를 정의 목록으로 배치하고, 선택한 강좌의 CSV는 필드/값 표로 보존한다. 오류: 입력을 확인하라는 제목, 서버가 보낸 이유, 다시 입력하기 동작을 한 덩어리로 둔다. 출처와 필수 고지는 모든 페이지에서 같은 위치에 둔다.

### 원칙

1. 서로 다른 두 강좌를 한 시간표에서 읽는다. A/B의 이름표와 시간 열을 모든 결과에서 반복한다.
2. 상태는 글자와 형태로도 전달한다. 체크된 요일은 체크 기호, 강한 외곽선과 색으로 표시한다. 포커스는 키보드로 모든 조작에서 보인다.
3. 정확한 사실을 먼저 보인다. 원문 강습반과 원본 금액 해석, 기준 월, 출처와 해시는 꾸밈 때문에 숨기지 않는다.
4. 단일 파란 머리판에만 대담함을 쓴다. 나머지 화면은 기능에 필요한 면과 구획으로 제한한다. 결과·근거 페이지는 긴 파란 히어로를 반복하지 않는다.
5. 새로운 동작을 만들지 않는다. 서버 렌더링, GET 폼, 네이티브 입력, 경로와 쿼리를 유지하고 JS를 추가하지 않는다.

## 2차 검토: AI 기본형과 대조한 수정 (구현 전 확정)

- **크림색+세리프+흙색**, **검정+형광 포인트**: 둘 다 배제했다. 차가운 바탕과 코발트는 시설의 강습 안내판을 위한 선택이며 글꼴도 한국어 안내 고딕 하나로 제한했다.
- **가는 선·직각·신문형 다단**: 초기 구상에는 모든 요소를 직각으로 나누는 안이 있었다. 선만 바꾼 신문형 템플릿이 될 수 있어 버렸다. 최종안은 입력 전체를 묶는 12px 외곽, 4px 입력, 6px 버튼, 직선 강좌 행을 구분한다. 행을 가르는 선은 A/B 비교와 필드/값 대응에만 쓴다.
- **같은 모양의 둥근 카드와 그림자**: 사람별로 떠 있는 카드를 없애고 하나의 입력판 내부 두 열로 통합했다. 결과도 가로 시간표 행, 변경 제안은 굵은 옆선, 근거는 표로 역할을 구분했다. 그림자는 없다.
- **상투적 히어로와 큰 통계**: 장식용 시간표 예시와 큰 강좌 수를 삭제했다. 실제 요일 입력이 첫 화면의 특징이 되며, 기준 월은 정확한 보조 정보 크기로 둔다.
- **불필요한 영문 소제목과 번호**: 영문 대문자·넓은 자간·소제목용 라벨을 없앴다. 동시/연속은 단계가 아니므로 01/02/03 번호를 삭제한다. A/B는 실제 두 사람의 입력 식별자이므로 유지한다.
- **메타데이터를 가운데점으로 나열**: 강좌번호·기준 월·금액·강습반을 각각 문장 또는 라벨/값으로 분리한다. 요일은 쉼표로 읽는다. 엔진이 반환한 변경 제안 문장은 UI에서 재작성하지 않아 계산 의미를 보존한다.
- **링크 끝 화살표와 단어 하나만 강조하는 제목**: 둘 다 삭제한다. 링크는 밑줄과 정확한 동작명, 버튼은 면과 외곽선으로 식별한다.
- **모든 곳에 움직임**: 페이지 등장 효과, 카드 부유 효과, 자동 애니메이션을 두지 않는다. 축소 모션 환경에서도 동일한 정보가 보인다.
- **과한 장식 한 가지 제거**: 초안의 스포츠 아이콘/레인 로고를 덜어냈다. 실제 요일 선택판 자체가 이 서비스의 표식이다. 기관 공식 로고처럼 보이는 모양도 만들지 않는다.

이 검토를 마친 최종안을 기준으로 템플릿과 단일 CSS를 작성한다. 강좌 계산·수집·서버 응답은 수정하지 않는다.

## 구현 후 검토

### 화면을 보고 덜어낸 것

- 실제 스크린샷에서 360px 결과의 센터명·강좌별 기준 월이 A/B 비교를 길게 만드는 것을 확인했다. 강좌번호를 네이티브 `details`의 제목으로 두고 그 아래에 두 정보를 펼치도록 수정했다. 수업 시간, 회비, 강습반 원문, 공통 요일과 겹침/간격은 계속 보인다. 전체 데이터 기준 월과 필수 고지는 모든 페이지 하단에 유지한다.
- 모바일에서 제목 설명의 줄바꿈을 없앨 때 문장이 붙어 보이는 문제를 수정했다.
- 입력 경계는 보조 글자색과 흰색을 70:30으로 섞어 구조 구분선보다 선명하게 했다. 흰 배경 대비 약 3.18:1이며, 체크 표시와 포커스 외곽선도 별도로 있다. 색 토큰은 추가하지 않았다.

### 검증 결과

- 기존 테스트를 수정하지 않고 `.venv/bin/python -m pytest` 통과: **80 passed, 1 warning**. 경고는 기존 FastAPI/Starlette 테스트 클라이언트의 의존성 사용 중단 안내다.
- 로컬 Uvicorn 서버 `127.0.0.1:8765`에서 실제 응답 검증. `/`, 제공된 데모 `/plan`, `/evidence`, 선택한 강좌 두 개의 `/evidence`는 200, 음수 예산은 422, 없는 경로는 404였다. 95,000원/TRX 조건의 결과에서도 실제 5,000원 변경 제안과 135,000원 근거를 확인했다.
- 각 응답에서 필수 고지 1회, 데이터 기준 월, 데이터셋 링크, 금액 해석과 강습반 원문 표시 안내를 검사했다. `/meta` 응답의 실제 파일 해시·수집 시각을 `/evidence` 본문과 대조했다. 원본 CSV의 비정상적인 날짜 표기도 보존된다.
- Chromium에서 1280px, 768px, 360px 각각 입력·예시·결과·변경 제안·근거·원본 행·오류를 촬영해 총 21개 화면의 가로 넘침이 없음을 확인했다. 대표 스크린샷을 직접 보고 검토했으며 임시 이미지는 `/tmp/kspo-ui-review/`에 있다.
- 실제 예시 폼 제출과 135,000원 결과, A/B 요일 독립 선택, Space 키로 체크 변경, 공유 URL 펼침, 원문 근거 이동을 확인했다. 네 화면의 표시된 조작 요소 57개에서 포커스가 보였고, Enter로 강좌 상세 펼침 및 본문 건너뛰기가 동작했다. 축소 모션 설정도 확인했다.
- 경로, 쿼리, 응답 데이터, 수집·계산 코드, 런타임 의존성과 테스트 파일은 변경하지 않았다. 새 JS나 외부 리소스 요청도 없다.
