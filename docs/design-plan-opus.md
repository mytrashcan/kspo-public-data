# 함께 운동 시간표 — 디자인 계획 (opus 안)

## 0. 주제와 화면의 일

- **대상**: 같은 체육센터(일산스포츠센터)에 함께 다니고 싶은 두 사람. 부부, 부모와 자녀, 친구. 한 사람이 휴대폰으로 둘의 조건을 받아 적는다.
- **화면의 일**: 두 사람의 요일과 시간을 *같은 칸에 나란히* 놓아 보는 것. 맞으면 어느 요일 몇 시에 둘이 각자 어디에 있는지, 안 맞으면 무엇을 얼마나 바꾸면 되는지.
- **주제의 재료**: 체육관 코트 바닥. 초록 아크릴 바닥 위에 노란 라인이 그어진 다목적 코트, 시설 게시판에 붙은 주간 강습 시간표, 출석부의 요일 칸. 색과 형태는 여기서 가져온다. 기관 로고나 사진 흉내는 내지 않는다.

## 1. 1차 계획

### 색 (5개)

| 이름 | 값 | 역할 |
| --- | --- | --- |
| 코트 초록 `--court` | `#1E5B49` | **A 사람**의 색. 주 동작 버튼, 포커스 테두리 |
| 라인 노랑 `--line` | `#F1C232` | **B 사람**의 색. 코트 라인 페인트 |
| 먹 `--ink` | `#1A2E28` | 본문. 초록 기운이 있는 먹색으로 코트 초록과 한 계열 |
| 회초록 `--muted` | `#56655F` | 보조 글. 흰 바탕 대비 6.0:1 |
| 바닥 `--floor` | `#E4EBE6` | 시간표 판의 바닥면 |
| 종이 `--paper` | `#FFFFFF` | 페이지 바탕 |

A는 어둡고 B는 밝다. 흑백으로 인쇄해도, 색각 이상이어도 A(진한 면)·B(밝은 면)·겹침(두 색 사선)이 명도만으로 구분된다. 여기에 A/B 글자를 항상 함께 둔다.

### 서체

- 한 가족: `Apple SD Gothic Neo` → `Pretendard` → `Malgun Gothic` → `sans-serif`. 외부 글꼴 요청 없이 사용자 기기의 한국어 고딕을 쓴다. 한국 공공시설 게시물의 문법이 고딕이다.
- 배율(Elements of Typographic Style의 고전 배율): 12 · 14 · 16 · 18 · 21 · 28 · 36. 굵기는 400 / 600 / 800 세 단계만.
- 서체가 하는 일: **시각**. `18:00–18:50`, 요일 글자, 금액은 `tabular-nums`로 자리를 맞추고 결과 문장과 시간표에서 가장 큰 활자가 된다. 소제목 위 라벨, 대문자 영문, 한 단어 강조는 없다.
- 본문은 왼쪽 정렬, 한 줄 60자 안팎. 금액은 비교하는 열에서만 오른쪽 정렬.

### 배치

**입력(`/`) — 출석부 한 장.** 두 사람을 좌우 패널로 나누지 않고, 한 장의 표에서 *행 = 조건, 행 안의 줄 = A와 B*로 나란히 적는다. 요일 행은 월–일 7칸 열을 A와 B가 공유하므로, 둘이 겹치는 요일이 세로로 바로 보인다. 그 아래 세 번째 줄이 "둘 다" 표시줄: 같은 열에서 A와 B를 모두 고르면 그 칸에 `함께`가 뜬다(CSS `:has()`만 사용, JS 없음).

```text
함께 운동 시간표                                       조건 입력  데이터 근거
───────────────────────────────────────────────────────────────────────────
둘이 같은 날 갈 수 있는 강좌를 찾아요                         (h1 36)
일산스포츠센터 2026-10 강좌 155개에서 두 사람 조건에 모두 맞는 짝을 찾고,
없으면 무엇을 바꾸면 되는지 알려 드려요.          예시 채우기

요일          월    화    수    목    금    토    일
         A   [ ]  [██]  [ ]  [██]  [ ]  [ ]  [ ]
         B   [ ]  [▒▒]  [ ]  [▒▒]  [ ]  [ ]  [ ]
                  함께        함께
시간     A  [18:00] 부터 [19:00] 까지   B [18:00] 부터 [19:00] 까지
월 회비  A  [100000] 원까지             B [ 70000] 원까지
선호 종목 A [모든 종목 v]              B [모든 종목 v]
뺄 종목   농구 [A][B]   요가 [A][B]   TRX [A][B]   검도 [A][B] ...
          (종목 × 사람 칸. 누른 칸에 사선이 그어진다)
                                     [두 사람 조건으로 찾기]
```

360–390px에서는 왼쪽 행 이름이 각 행 위로 올라가고, 요일 7칸은 그대로 유지된다(7 × 40px). 시간·회비·선호 종목은 A줄, B줄로 쌓인다.

**결과(`/plan`) — 코트 위의 주간 시간표가 주인공.**

```text
A 화, 목 18:00–19:00 월 100,000원까지 모든 종목      [조건 수정]
B 화, 목 18:00–19:00 월 70,000원까지 모든 종목       같은 조건 공유 링크 ▸

화, 목 18:00에 같은 시간 운동할 수 있어요                       (h1)
겹치는 시간 50분. 두 사람 월 회비 합계 135,000원.

┌ 주간 시간표 (바닥 #E4EBE6) ──────────────────┐  A  TRX 18시(화목)
│     월    화        수    목        금 토 일  │     18:00–18:50  월 100,000원
│ 17                                           │     강습반 원문 성인남여 …
│ 18       [A▓][B░]        [A▓][B░]            │  B  농구 18시(초등3~.화목)신봉주
│ 19         ↑ 가운데 사선 띠 = 겹치는 50분      │     18:00–18:50  월 35,000원
│ …  (06–24시 전부, 한 시간 34px)               │  [원문 근거 보기]
└───────────────────────────────────────────────┘

동시 조합 1개                         연속 조합 0개
 18:00–18:50 TRX… + 농구…  겹침 50분 135,000원 (보는 중)
```

- 한 요일 열은 **A 레인 | 겹침 띠 | B 레인** 세 줄기로 나뉜다. 이전 판은 A와 B가 같은 칸에 겹쳐 그려져 B가 A를 덮었다. 이제 둘은 나란히 서고, 그 사이 띠가 겹치는 분만큼만 초록·노랑 사선으로 칠해진다. 지퍼처럼 두 수업을 잇는다.
- 공통 요일 머리칸은 굵은 글자와 아래 막대로 표시(색만으로 구분하지 않음).
- 조합 없음: h1이 "지금 조건으로는 함께 갈 조합이 없어요"가 되고, 시간표 자리에 **최소 변경 제안**이 바로 온다. 빈 목록 두 개를 먼저 보여주지 않는다.

**근거(`/evidence`)** — 파일 정보는 2열 정의 표, 두 강좌의 원본 CSV 행은 넓은 화면에서 A | B 나란히(같은 필드끼리 눈으로 비교). **오류** — 무엇이 틀렸는지 한 문장, 고칠 곳으로 가는 버튼 하나.

### 원칙

1. **나란히가 기본 단위.** A와 B는 어디서나 같은 행/열에 나란히. 요일 열, 시간표 레인, 원본 행 비교 모두.
2. **A는 초록 면, B는 노랑 면, 겹침은 두 색 사선.** 이 세 가지 표지가 화면 전체의 유일한 장식이다.
3. **곡률에 뜻이 있다.** 누를 수 있는 것(입력, 버튼, 요일·종목 칸)은 6px, 데이터 면(시간표, 표)은 각진 모서리. 그림자 없음.
4. **사실은 문장으로.** 메타를 점으로 잇지 않고, 기준 월·출처·금액 해석은 짧은 문장으로 쓴다.
5. **움직임은 응답에만.** 칸을 누를 때 120ms 색 전환 하나. 자동 등장 효과 없음.

## 2. 계획 검토 — AI 기본형 목록과 대조

비슷한 요청("두 사람 운동 시간 맞추기 앱")을 백지에서 받았다면 무엇을 그렸을지 먼저 적고 비교했다: 파란/보라 그라데이션 히어로, 큰 숫자 통계 3개, 사람별 둥근 카드 두 장, 결과 카드 목록. 이 계획에서 그 흔적을 찾아 고쳤다.

| 항목 | 1차 계획에서 걸린 것 | 수정 |
| --- | --- | --- |
| 크림+세리프+테라코타 / 검정+형광 | 해당 없음. 다만 처음엔 시간표 판을 *진초록 바탕에 노랑 블록*으로 그리려 했다 — "어두운 바탕에 강한 한 색"의 변형이다. | 판 바닥은 밝은 `#E4EBE6`, 초록은 A의 면으로만 쓴다. 어두운 면적이 페이지를 지배하지 않는다. |
| 브로드시트 가는 선·직각 | 출석부 안은 자칫 "가는 선으로 칸 나눈 표"가 된다. | 입력 행 사이에 선을 긋지 않고 간격(28px)과 왼쪽 행 이름 열로 구분. 선은 시간표 격자와 원본 표에만. 누르는 칸은 6px 곡률로 표와 구별. |
| 같은 카드·같은 곡률·같은 그림자 | 1차 결과 안에 오른쪽 상세를 "카드"로 그렸다. | 상세는 판 옆의 정의 목록(테두리 없음). 카드 컴포넌트가 하나도 없다. 그림자 0개. |
| 대문자 라벨·눈썹 라벨 | 시간표 위 "주간 시간표" 작은 회색 라벨이 들어가 있었다. | 삭제. 판 자체가 시간표임이 명백하다. 접근성 이름은 `aria-label`로만. |
| `A · B · C` 메타 | 조합 행 "TRX · 18:00 · 화, 목" 형태를 쓰려 했다. | 열로 분리(시간 / 이름 / 겹침 / 합계). 엔진이 만든 변경 문장 속 `·`, `→`는 계산 결과 원문이라 손대지 않는다. |
| `→` 링크, 단어 하나 강조 | 결과 h1에서 시간만 굵게 하려 했다. | h1 전체를 한 굵기. 링크·버튼에 화살표 없음. |
| 숫자 번호 01/02 | 입력 행에 번호를 붙일까 했으나 조건은 순서가 아니다. | 번호 없음. |
| 모노스페이스 작은 데이터 | 파일 해시를 고정폭으로 쓰려 했다. | 같은 고딕 + `tabular-nums`. 해시는 4자 단위로 끊어 읽기 쉽게(값 자체는 그대로 출력, CSS로만 줄바꿈 허용). |
| 히어로 | 입력 페이지 h1 오른쪽에 "기준 월" 상자를 둘 뻔했다 — 거절된 구성 그대로다. | 기준 월은 소개 문장 안의 사실로만. 오른쪽 상자 없음. 첫 화면의 특징은 요일 출석부다. |
| 장식 하나 덜기 | 브랜드 옆에 A/B/겹침을 그린 작은 로고 마크를 계획했다. | 뺐다. 같은 표지가 바로 아래 요일 칸과 시간표에서 실제 정보로 나온다. |

검토 후 남은 "대담함"은 한 곳: **세 줄기(A | 겹침 띠 | B)로 쪼갠 요일 열**. 나머지는 조용히 둔다.

## 3. 이번에 이전 시도와 다르게 간 것

- **좌우 사람 패널 → 한 장의 출석부.** 이전 안은 A 패널과 B 패널을 나란히 두어, 둘의 요일이 맞는지 보려면 눈이 좌우를 왕복해야 했다. 이번에는 같은 요일 열을 A·B가 공유하고, 둘 다 고른 열에 `함께`가 뜬다. 앱의 질문("같은 날 되나?")을 입력 단계에서 이미 보여준다.
- **시간표의 덮어쓰기 버그를 형태로 해결.** 이전 판은 A와 B를 같은 칸 전체 폭에 그려 B가 A를 가리고, 사선 띠가 둘 다를 덮었다. 이번엔 A 레인, 겹침 띠, B 레인으로 나눠 두 블록과 겹침이 동시에 보인다. 06–24시 판은 한 시간 34px로 줄여 화면 하나에 들어온다.
- **파랑/벽돌 → 코트 초록/라인 노랑.** 이전 색은 어떤 서비스에도 쓰일 법한 파랑이었다. 체육관 바닥의 색으로 바꾸고, A 어둡게·B 밝게 명도를 갈라 색 없이도 구분되게 했다.
- **빈 결과에서 제안이 먼저.** 이전엔 "없음" 상자 두 개 아래에 제안이 묻혀 있었다. 이제 조합이 없으면 제안이 시간표 자리를 차지한다.
- **결과의 첫 문장이 답.** "두 사람의 운동 시간표" 같은 제목 대신 "화, 목 18:00에 같은 시간 운동할 수 있어요"처럼 선택한 조합에서 만든 문장이 h1이다.
- **근거 페이지에서 A/B 원본 행을 나란히.** 같은 필드를 좌우로 비교할 수 있다.

## 4. 구현 후 검토 (스크린샷을 보고 고친 것)

1. **시간표가 비어 있었다.** 첫 빌드에서 요일 머리칸과 블록이 하나도 그려지지 않았다. `cards.html` 매크로를 `import`할 때 컨텍스트가 넘어가지 않아 `days`가 비어 있었다. 이전 판의 머리칸이 빈 것도 같은 원인이었다. `import … with context`로 고쳤다.
2. **모바일 스크린샷이 가짜 390px였다.** 헤드리스 Chrome은 창 폭을 500px 아래로 줄이지 않는다. 390px 폭의 iframe 안에서 렌더링해 실제 390px 배치를 확인하도록 촬영 방식을 바꿨다.
3. **빈 코트 위의 작은 블록.** 06–24시 판에서 50분 수업은 작다. 시간 범위를 줄이는 대신, 각자 입력한 시간 범위를 그 사람 레인에 흰 띠로 깔았다. 이제 빈 판에도 정보가 있다. 연속 조합에서는 "A는 17시, B는 18시, 둘 다 17–22시 안"이 한눈에 읽힌다.
4. **제안 블록의 격자 버그.** 오른쪽 강좌 상세가 왼쪽 다섯 행을 늘려 버튼이 키 큰 덩어리가 됐다. 왼쪽을 한 묶음으로 감싸고, 오른쪽에 "이 제안으로 성립하는 두 강좌"와 합계를 붙였다.
5. **h1 문장.** "화, 목, 두 사람…"의 쉼표 연쇄를 "화, 목요일에 두 사람 수업 시간이 50분 겹쳐요"로 바꿨다.
6. **모바일 시간 입력.** "오후 06:00"이 잘리고 한 사람의 시간이 두 줄로 쪼개졌다. 입력 폭과 간격을 다시 잡아 A줄과 B줄이 각각 한 줄에 들어가게 했다.
7. **액세서리 하나 덜기.** 합계, 제안 합계, 제출 줄에 쓴 3px 먹선을 1px 구획선으로 낮췄다. 굵은 선은 "표의 머리"(입력지 상단, 목록 제목, 원본 표 캡션)에만 남겼다.
8. 공유 링크 `summary`에 `display:flex`를 줘 펼침 표시가 사라졌던 것을 되돌렸다.

### 검증

- `.venv/bin/python -m pytest`: 80 passed. 테스트는 고치지 않았다(단언하는 문자열 `예시 채우기`, `동시 조합`, `최소 변경 제안`, `변경한 조건으로 다시 보기`, `조건을 확인해 주세요`, `공유 URL` 등을 유지).
- 고지 문장 외에 금지 문자열 3종이 템플릿·CSS에 없음을 확인. 링크·버튼에 `→` 없음(제안 문장 속 `→`는 엔진 출력 원문).
- 촬영: 1360×1600, 390×1400. 입력, 예시 입력, 결과 상단, 시간표+목록, 원문 근거, 최소 변경 제안, 오류, 제외 종목이 눌린 상태, 동시 5개·연속 14개인 조합에서 연속 조합을 고른 상태.
- 상태는 색만으로 구분하지 않는다: 요일은 채움과 테두리, 굵기로, 제외는 채움과 사선으로, 공통 요일은 `함께` 글자와 막대로, 선택한 조합은 "시간표에 표시 중" 글자로 표시한다. 포커스는 3px 초록 외곽선. 움직임은 칸 색 전환 120ms 하나이고 `prefers-reduced-motion`에서 끈다.
- `main.py`, `planner.py`, `ingest.py`, 경로·쿼리·응답은 그대로다. JS도 없다. "둘 다" 표시줄은 CSS `:has()`만 쓰고, 지원하지 않는 브라우저에서는 줄이 비어 있을 뿐 폼은 그대로 동작한다.

## 5. 3차 — "함께 운동해요"로 다시 맞추기

### 이 화면이 줘야 하는 느낌 (한 문장)

> 화요일 저녁, 한 사람의 휴대폰을 둘이 같이 들여다보며 "그럼 같이 가서 너는 농구, 나는 TRX 할까?"를 정하고, 정확한 시각과 한 달 회비를 손에 쥔 채 화면을 닫는 몇 분.

이 문장에 대고 모든 결정을 다시 확인했다. "둘이 같이 보나?", "말하듯 읽히나?", "시각·금액·근거·한계가 그대로 남았나?"를 물었다. 색은 바꾸지 않았다. 따뜻함은 말투, 리듬, 그리고 두 사람을 어떻게 부르느냐에서 나온다.

### 시간 입력: 무엇을 골랐고 왜

**결정: 한 사람에 하나씩, "18:00 – 22:00"처럼 하나의 값으로 읽히는 테두리 상자. 상자의 두 반쪽이 각각 네이티브 `<select>`이고, 30분 단위이며 끝 시각에 24:00이 있다.**

| 후보 | 버린 이유 |
| --- | --- |
| 24시간 띠 위의 범위 슬라이더 | 네이티브 `range`는 손잡이가 하나다. 두 손잡이 범위와 현재 값을 보여 주는 `<output>`은 JS가 있어야 맞게 움직인다. 엄지로 5분, 10분 단위를 맞추다 미끄러지기 쉽다. |
| `<input type="time">` 두 개 | 24:00을 표현할 수 없다(최대 23:59). iOS 휠, Android 시계판, 데스크톱 스피너가 제각각이다. 오전/오후 표기 때문에 값이 잘린다(2차 검토 6번). |
| 자주 쓰는 시간대 프리셋 | 프리셋 하나가 `a_start`와 `a_end` 두 값을 보내야 한다. 라디오나 버튼 하나는 값을 하나만 보낸다. 링크로 만들면 아직 제출하지 않은 요일과 회비 입력이 사라진다. JS 없이는 맞게 만들 수 없다. |
| "18:00–20:00"을 직접 적는 텍스트 칸 하나 | 휴대폰 숫자 자판에는 `:`와 `–`가 없어 자판을 바꿔야 한다. 오타가 생길 수 있고, 쿼리 파라미터(`a_start`, `a_end`)를 바꾸지 않는다는 규칙에도 어긋난다. |
| 숫자 칸 두 개(시, 분) | 한 사람당 칸이 넷이 되고, 탭 수와 잘못 누를 곳이 두 배가 된다. |

`<select>`가 남은 이유는 일관성이 아니라 다음 네 가지다.
- **누르는 횟수가 가장 적다.** 칸 하나에 탭 두 번(열기, 고르기)이면 끝난다. 휴대폰에서는 OS의 휠이나 목록이 열려 엄지 하나로 쓸 수 있다.
- **잘못된 값이 들어갈 수 없다.** 고를 수 있는 값이 모두 `HH:MM` 형식이고, 끝 목록에는 24:00이 있다.
- **값이 늘 보인다.** 아무것도 열지 않아도 상자에 "18:00 – 22:00"이 21px 굵은 숫자로 보이고, 결과 페이지의 조건 문장에도 같은 표기로 찍힌다.
- **한 줄 안에서 위젯이 섞이지 않는다.** 시작도 끝도 같은 네이티브 목록이다. `appearance: none`으로 테두리를 하나로 합쳐 "시작 / 끝 두 칸"이 아니라 "시간대 하나"로 읽히게 했다.

목록 길이도 줄였다. 이전에는 10분 단위로 144개였는데, 이제 30분 단위로 48개다. 데이터 155개 강좌 중 152개가 정시에 시작하고 147개가 :50에 끝나므로 30분 단위로 놓치는 강좌가 없다. URL로 들어온 다른 값(예: 18:10)은 목록에 그대로 끼워 넣어 선택된 상태를 유지한다.

### 두 종목 컨트롤: 하나의 언어, 두 가지 뜻

- 선호 종목 드롭다운을 없앴다. 이제 종목 표가 하나다. 행은 종목이고, 열 묶음은 **✓ 이것만 (나 | 짝)**과 **✕ 빼기 (나 | 짝)** 두 개다. 같은 종목이 같은 줄에 있어서, 한 줄을 보면 "나는 TRX만, 짝은 TRX 빼고"를 함께 읽을 수 있다.
- 맨 위 행은 **모든 종목**이다. 사람마다 라디오 하나가 기본으로 눌려 있고, 빼기 칸은 없다.
- 칸 모양과 크기, 사람 색은 같다. 뜻은 색이 아닌 세 가지로 구분한다. (1) 눌렀을 때 칸 안 기호(✓ / ✕), (2) 열 머리말("✓ 이것만" / "✕ 빼기"), (3) 동작 차이: 선호는 라디오라서 한 사람당 하나, 빼기는 체크박스라서 여러 개. 선호로 고른 종목은 이름도 굵어진다. 화면 낭독기는 칸마다 "나: TRX만 하고 싶어요", "짝: 요가 빼기"를 읽는다.
- 2차의 사선 표시는 뺐다. ✕ 기호와 사선, 글자가 겹쳐 지저분했다(스크린샷 5).
- 테스트의 폼 파서가 라디오를 체크박스처럼 "checked일 때만 제출"하도록 고쳤다. 브라우저 동작과 같아졌을 뿐이고, 단언은 바꾸지 않았다.

### 말투와 구성에서 바꾼 것

- **A / B → 나 / 짝.** 휴대폰을 든 사람이 "나", 같이 갈 사람이 "짝"이다. 소개 문단 바로 아래에 표지 두 개와 그 뜻을 둔다. 쿼리 키(`a_`, `b_`)와 엔진 문장의 `A:`/`B:` 접두는 그대로 두고 표시만 바꿨다(`cards.html`의 `WHO`).
- **양식 행 이름 → 질문.** "사용 조건/요일/시간/예산"처럼 같은 무게였던 행 이름을 "언제 같이 갈 수 있어요?", "몇 시부터 몇 시까지 돼요?"로 바꾸고 크게(24px) 썼다. 회비와 종목은 구분선 아래 "정하지 않아도 돼요" 묶음에 작게(18px) 넣었다. 왼쪽 200px 라벨 열과 3px 먹선 머리를 없애 사무용 서식 느낌을 뺐다.
- **결과의 첫 문장은 둘이 할 일.** "화, 목요일 18:00에 같이 가서, 각자 운동할 수 있어요" 다음 줄에 "나는 TRX, 짝은 농구. 두 수업이 50분 겹쳐요. 둘이 합쳐 한 달 135,000원이에요."를 둔다. 연속 조합은 "내 수업이 끝나고 10분 뒤에 짝의 수업이 시작돼요."라고 쓴다.
- **조건 요약은 필터 줄이 아닌 문장.** "나는 화, 목 18:00–19:00에 돼요. 회비는 한 달 100,000원까지, 종목은 아무거나." 고른 시간대가 이 문장 안에 그대로 찍힌다. 위치도 h1 아래로 옮겨서, 답이 먼저 오고 조건이 뒤따른다.
- **시스템이 아닌 상황을 말한다.** "지금 조건으로는 함께 갈 조합이 없어요" 대신 "지금 조건으로는 같이 갈 수 있는 날이 없어요"라고 쓰고, 제안 묶음 제목은 "이렇게 바꾸면 같이 갈 수 있어요"다. 목록 제목은 "같은 시간에 각자 / 한 사람씩 이어서"이고, 정확한 용어(동시 조합 N개 / 연속 조합 N개)는 옆에 작게 남겼다.
- **같은 무게의 표 → 문장과 작은 글씨.** 제안 비용의 세 칸 정의 목록(추가 월 예산 / 추가 요일 / 시간 범위 확장, 0도 표시)은 0이 아닌 것만 "더 늘리는 것 회비 한 달 +5,000원"으로 보여 준다. 다 0이면 "회비, 요일, 시간은 지금 그대로예요."라고 쓴다. 강좌 상세의 여섯 줄 표는 "TRX, 한 달 **100,000원**" 한 문장과 13px 작은 글씨(강습반 원문, 강좌번호, 장소, 데이터 기준)로 나눴다.
- **단단한 부분은 그대로 뒀다.** 정확한 시각, 월 회비, 기준 월, 출처, 해시, 수집 시각, 고지문, 월 회비 해석과 강습반 원문 안내가 그대로 있다. 결과 옆에는 "나이·성별로 들을 수 있는지는 확인하지 않아요."를 한계로 밝힌다. 근거 페이지의 원본 표는 표가 맞는 자리라서 그대로 두었다.
- 공유 링크는 "짝에게 보낼 링크", 조건 수정은 "조건 바꾸기", 제출 버튼은 "같이 갈 수 있는 날 찾기"로 바꿨다.

### 스크린샷을 보고 고친 것 (`/tmp/shots_opus2/`)

1. 조건 문장이 "…괜찮고, 종목은 아무거나 / 괜찮아요"처럼 두 줄로 꺾였다. "…에 돼요. 회비는 한 달 N원까지, 종목은 아무거나."로 줄였다.
2. 제안 머리말의 "조금만 바꾸면 돼요"는 제안이 클 때 사실이 아니다. 지웠다.
3. "더 여는 만큼"은 어색해서 "더 늘리는 것"으로 바꿨다.
4. 모바일에서 select 반쪽이 늘어나 숫자는 왼쪽, 화살표는 오른쪽 끝으로 떨어졌다. 숫자를 가운데 정렬했다.
5. 회비 칸 자리표시자 "상관없어요" 뒤에 "원까지"가 붙어 문장이 이상해졌다. 자리표시자를 빼고, 묶음 머리말("비워 두면 금액과 종목을 따지지 않고 찾아요")에 뜻을 맡겼다.
6. 빼기 칸의 사선과 ✕ 기호가 겹쳤다. 사선을 지웠다.

## 6. 4차 — 두 사람에서 네 사람까지

미감은 그대로 두고 수용 인원만 넓혔다. 코트 초록은 첫째 사람, 라인 노랑은 둘째 사람이다. 출석부 입력과 주간 시간표도 그대로다.

### 규칙 (엔진)

- `search(courses, *people)`, `plan(courses, *people)`는 2–4명을 받는다. 범위를 벗어나면 `ValueError`.
- 조합 `Combination(courses, days, overlap_minutes)`의 `courses`는 사람 순서대로 한 사람에 한 강좌다. 강좌는 모두 서로 달라야 하고, 센터·달·**마치는 시각**이 같아야 한다. 공통 요일은 모든 강좌 요일의 교집합이고 비어 있으면 안 된다. 겹침은 `종료 − max(시작)`이다.
- 같은 (센터, 달, 종료 시각)끼리만 묶어서 사람 순서대로 깊이 우선으로 고른다. 고를 때마다 요일 교집합이 비면 그 가지를 버린다. 제한 없는 네 사람도 순서 있는 조합 5,568개로 14ms 걸린다. 그래서 최소 변경 계산은 2인 때처럼 전체 조합을 훑는 방식을 유지했다.
- 정렬은 합계 오름차순, 겹침 내림차순, 강좌번호 순이다.
- 최소 변경은 사람마다 따로 계산한다(`A:`…`D:` 접두). 요일 추가, 예산 증액, 시간창 확장, 종목 제한 완화다. 유형마다 최소 하나를 고르고, 혼자 성립하는 유형이 없으면 함께 바꿀 변경 하나를 고른다. **바꾼 조건으로 다시 검색해 증거 조합이 실제로 나올 때만** 보여 준다. 이 보장은 2인 때와 같다.
- `pick=` 토큰은 강좌번호를 `:`로 이은 값이고, 이제 순서까지 맞아야 고른다. 집합 비교였던 이전 방식은 같은 강좌 두 개를 사람만 바꾼 조합을 구분하지 못했다. 기존 링크는 `a:b` 순서로 만들어졌으니 그대로 열린다.

### 이름: 나 / 짝, 그리고 나 / 2번 / 3번 / 4번

- **두 사람이면 나와 짝**이다. 바꾸지 않았다.
- **세 사람부터는 나, 2번, 3번, 4번**이다. 표지는 `나`, `2`, `3`, `4` 한 글자다. "짝"은 둘일 때만 맞는 말이라 셋부터는 쓰지 않는다. "짝은 배드민턴, 3번은 스쿼시"는 누가 누구의 짝인지 묻게 만든다.
- 왜 번호인가: 체육관에서 무리를 나눌 때 "번호!" 하고 세는 말이고, 출석부의 출석 번호와도 맞는다. 관계(친구, 가족, 동료)를 짐작하지 않는다. "나는 검도, 2번은 배드민턴, 3번은 스쿼시"는 소리 내어 읽어도 자연스럽다. 휴대폰을 든 사람은 끝까지 "나"다.
- 버린 것:
  - **둘째·셋째**: 한국어에서는 형제 순서로 먼저 읽힌다.
  - **가·나·다**: "나"가 겹친다.
  - **갑·을·병**: 계약서 말투다.
  - **이름 입력란**: 사람마다 칸이 하나 늘고, 쿼리 키도 새로 생긴다. 첫 글자가 같은 이름이 둘이면 표지가 같아진다.
- 색: C는 **하드코트 파랑** `#2B5C93`(흰 글자), D는 **체육관 마루** `#D39B5E`(먹 글자)다. 코트에 실제로 있는 색에서 골랐다. 순서대로 어둡게, 밝게, 어둡게, 밝게 번갈아 둔다. 같은 명도인 A와 C는 색상과 글자로 구분한다. 표지에는 늘 글자가 있고, 시간표 레인은 순서가 고정이라 위치도 신호가 된다.

### N 레인 시간표

- 한 요일 칸을 사람 수만큼 같은 폭의 레인으로 나눈다. 레인 i의 위치는 `--lane`/`--lanes` 두 변수로 계산하고, 레인 사이에 간격을 둔다.
- **겹치는 분은 레인 밑에 깔리는 사선 매트 한 장**이다. 2인 판에서는 두 블록 사이 10px 띠였다. N명일 때 그 띠를 사이사이에 그리면 띠가 N−1개로 쪼개져 "모두 함께인 시간"이 하나로 읽히지 않는다. 그래서 칸 전체 폭의 사선 면을 블록 아래에 깔았다. 블록 사이 간격과 양 끝으로 사선이 드러나서, 블록들이 한 장의 매트 위에 함께 서 있는 모양이 된다. 2인 판도 같은 방식으로 바뀌었다.
- 3–4명일 때는 **모두가 함께인 요일 칸을 넓힌다**. 공통 요일은 `(N−1)fr`, 나머지는 `1fr`이다. 390px, 3명이면 공통 요일 레인이 약 26px, 4명이면 약 24px라서 `나/2/3/4` 글자가 들어간다. 공통 요일이 아닌 칸은 어떤 사람의 수업이 다른 날에도 있다는 사실만 보여 주면 되므로 좁다. 그런 칸은 시작 시각을 빼고, 간격과 글자를 줄여 표지만 남겼다.
- 모바일에서 레인 4개가 끝까지 남지 않는 경우: 네 사람의 공통 요일이 7일 모두라면 레인 하나가 10px 남짓이 된다. 이때는 글자 표지가 잘릴 수 있다. 그래서 범례에 "요일 칸 안에서 왼쪽부터 나, 2번, 3번, 4번 순서예요."를 적어 **위치가 이름을 대신하게** 했다. 각 블록에는 화면 낭독기용 문장("화요일 3번의 수업 스쿼시 … 21:00–21:50")이 있다. 시간표 오른쪽(모바일에서는 아래)의 강좌 목록에는 표지와 이름이 다 있다. 요일별 세로 목록으로 바꾸는 안도 검토했다. 하지만 그러면 이 앱의 대담한 한 곳인 "나란히 선 레인"이 사라진다. 실제 데이터의 3–4인 조합은 공통 요일이 둘인 경우가 대부분이라 판을 지켰다.

### "한 사람 더" — 스크립트 없이 입력값을 지키는 방법

- **링크가 아니라 같은 폼의 두 번째 제출 버튼**이다. `<button type="submit" formaction="/" name="people" value="3">한 사람 더</button>` 링크는 아직 제출하지 않은 요일, 시간, 회비, 종목을 담을 수 없어서 누르는 순간 입력이 사라진다. 이 버튼은 폼 전체를 `/`로 보내고, `/`는 받은 값과 `people=3`으로 한 사람이 더 있는 출석부를 다시 그린다. 그래서 적은 값이 모두 남는다. JS가 전혀 없다.
- **마지막 사람 빼기**도 같은 방식이다. 버튼 글자는 "4번 빼기"처럼 누구를 빼는지 말한다. 뺀 사람의 값은 조용히 버리지 않는다. 다시 그린 페이지에 "4번을 뺐어요. 적어 둔 조건이 아까우면 되돌리기를 눌러 주세요."를 띄우고, 되돌리기 링크에는 방금 보낸 쿼리(4번의 값 포함)와 `people=4`를 담는다.
- 입력란에서 Enter를 누르면 브라우저는 폼의 *첫* 제출 버튼을 쓴다. "한 사람 더"가 위에 있으므로, 폼 맨 앞에 보이지 않는 "같이 갈 수 있는 날 찾기" 제출 버튼을 하나 두었다(`tabindex=-1`, `aria-hidden`). 그래서 Enter는 늘 검색이다.
- 사람 수는 `/plan`에서는 쿼리에 있는 마지막 접두(`c_`, `d_`)로 정한다. 그래서 `c_*`, `d_*`가 없으면 지금까지와 똑같이 두 사람이고, `a_*`/`b_*`는 그대로다. `people`은 입력 페이지에서만 의미가 있고 결과 URL에는 들어가지 않는다.
- "세 사람 예시"(`/?example=3`)를 더했다. 검증된 검도·배드민턴·스쿼시 조합이 나오는 조건이다.

### 그 밖에 바꾼 것

- 요일 출석부의 "둘 다" 줄은 세 사람부터 "모두"가 된다. `.week-2/3/4`마다 `:has()` 규칙을 둬서, 모두 고른 요일에만 `함께`가 뜬다.
- 종목 표: 셋부터는 두 단 대신 한 단이다. 각 행은 `✓` 칸 N개, 간격, `✕` 칸 N개다. 격자 열은 `--n`으로 계산한다. 390px, 4명이면 30px 칸 8개와 종목 이름이 한 줄에 들어간다.
- 문장의 수사를 사람 수에 맞췄다(둘/셋/넷, 두/세/네). 예: "셋이 합쳐 한 달 197,000원이에요", "세 수업이 50분 겹쳐요". "짝에게 보낼 링크"는 셋부터 "같이 갈 사람들에게 보낼 링크"다. 메뉴 "둘이 정하기"는 "같이 정하기"가 됐다.
- `/evidence`는 `c_code`, `d_code`를 받는다. 앞 사람이 비어 있으면(예: `b_code` 없이 `c_code`) 400, 같은 번호가 있으면 400, 없는 번호면 404, 그 순서로 조합이 성립하지 않으면 422다. 원본 행은 두 열 격자에 사람 순서대로 놓인다.
- 기준 월, 출처, 해시와 수집 시각, 고지문, 월 회비·강습반 안내는 그대로다. 금지어 3종은 고지문 안에만 있다(3인 결과와 3인 근거 페이지도 테스트에 넣었다).

### 버린 안

- **모바일 4인은 시간표 대신 표**: "판이 주인공"이라는 원칙을 깨고, 데이터상 거의 생기지 않는 경우를 위해 흔한 경우를 희생한다.
- **사람마다 행을 나눈 시간표(요일 × 사람 행렬)**: 7×4 칸이 되어 "같은 시각에 함께"가 세로로 정렬되지 않는다.
- **겹침을 블록 위에 덮는 반투명 띠**: 1차 판의 덮어쓰기 버그(띠가 블록을 가림)로 돌아간다.
- **JS로 행 추가**: 필요 없다. 폼 제출 버튼 하나로 값이 보존된다.
